# Contributing

Thanks for helping. FHIRBridge handles patient data, so a few rules are stricter than usual.

## Ground rules

- **Never commit real patient data**, not even "anonymized" samples. Fixtures are synthetic and
  generated by `scripts/generate-fixture.mjs`.
- Read the privacy invariants in [ARCHITECTURE.md](ARCHITECTURE.md#privacy-invariants). A change
  that lets any identifier, date offset or raw warning reach model-facing output, logs or error
  messages will not be merged.
- Report vulnerabilities privately; see [SECURITY.md](SECURITY.md).

## Setup

```bash
npm ci
npm run lint        # tsc --noEmit, strict
npm test            # unit + integration (vitest)
npm run build
npm run test:e2e    # the built CLI: exit codes, stdout/stderr, PHI-free errors
npm run bench       # fails if planted PHI or the date offset leaks
npm run coverage    # thresholds: 85% lines/functions/statements, 75% branches
```

Node.js ≥ 22.12.

## Making a change

1. Write the failing test first. De-identification changes need a regression test that plants
   the identifier and asserts it does not appear anywhere in the serialized output.
2. Keep layers behind the contracts in `src/types/pipeline.ts`. Adapters (CLI, MCP, SDK) carry no
   clinical logic.
3. Throw `FhirBridgeError` with a PHI-free message for anything a user can hit; never interpolate
   input values into messages.
4. Log through `src/logger.ts` with identifier-like values only.
5. Relative imports end in `.js`; type-only imports use `import type`; no `any`.
6. Run everything above before opening a PR. CI runs it on Ubuntu and Windows with Node 22 and 24,
   plus CodeQL, a Docker build and an npm-pack content check.

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/).
